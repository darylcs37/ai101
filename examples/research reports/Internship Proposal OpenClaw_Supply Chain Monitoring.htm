Executive Summary

This proposal outlines a structured internship project to build a live, 24/7 AI agent team that autonomously monitors an international supply chain — detecting cascading delays, identifying root causes, and pushing flash reports to operational teams via Telegram — all without human intervention between monitoring cycles.[1][2]

The reference implementation, built by supply chain data scientist Samir Saci, was motivated by a real client problem: 18% of shipments arriving late to 67 global stores, even though every individual team reported hitting their own target. The root cause was systemic — cascading bottlenecks across handoff points that no single team owned.

The insight is not that LLMs are smarter than analysts — it is that agents can run continuously at scale.

Problem Statement

The "Everyone Is On Time Yet Shipments Are Late" Paradox

Luxury goods moving from a Milan distribution centre through customs, air freight, and local last-mile delivery pass through four distinct teams. Each team measures only its own step. A warehouse picking delay that pushes a shipment past a flight cut-off time creates a two-day cascading delay — but no team owns that threshold crossing.[2]

With 90+ late deliveries per day across 8 cities, manual CSV exports cannot keep pace. Analysts can review only a few cases per week. Store managers escalate every Monday, and team leads show up with conflicting spreadsheets.[4][2]

What AI Agents Solve

The solution is a team of four global and eight regional AI analyst agents, each scoped to a slice of the network, running hourly investigation cycles and pushing findings directly to operations via Telegram.[2][3]

System Architecture

The system has three distinct layers that mirror how a real operations team would be structured:[3][2]

Supply Chain Simulator (Python)
  ├─ Generates 500+ orders/day with realistic variability
  ├─ Simulates 8 process steps across 4 teams
  └─ Writes real-time state to TMS database (SQLite/Postgres)
          ↕ (SQL queries via OpenClaw tools)
OpenClaw Multi-Agent Gateway
  ├─ Marco  — Distribution Network Manager (global anomaly sweep)
  ├─ Elena  — Transportation Manager (misattributed delays)
  ├─ Giovanni — DC Operations Manager (warehouse throughput)
  ├─ Yuki  — Air Freight Manager (flight variability)
  └─ 8× Regional personas (Shanghai, Tokyo, Dubai, Riyadh, Seoul…)
          ↓ (Telegram flash reports every hour)
Telegram Channels
  ├─ #global-ops  ← Marco, Elena, Giovanni, Yuki
  └─ #shanghai, #tokyo, #dubai… ← regional agents

Phase 1 — Build the Supply Chain Simulator

Goal: A Python process that runs 24/7, continuously generating orders and updating their state in a TMS database.

Database Schema

CREATE TABLE orders (
    order_id      TEXT PRIMARY KEY,
    store_city    TEXT,
    store_id      TEXT,
    sku           TEXT,
    quantity      INT,
    created_at    TIMESTAMP,
    required_by   TIMESTAMP,
    status        TEXT
);

CREATE TABLE shipment_steps (
    step_id       INTEGER PRIMARY KEY AUTOINCREMENT,
    order_id      TEXT REFERENCES orders(order_id),
    step_name     TEXT,
    team          TEXT,
    target_hours  REAL,
    actual_hours  REAL,
    started_at    TIMESTAMP,
    completed_at  TIMESTAMP,
    delay_flag    BOOLEAN
);

Simulator Core (Python Snippet)

The simulator uses simpy to generate 500+ orders/day following a realistic inter-arrival distribution. Variability is injected using a log-normal distribution to replicate tail delays.

import simpy
import pandas as pd
import numpy as np
from datetime import datetime, timedelta

def simulate_step_duration(target_hours: float, sigma: float) -> float:
    """Log-normal variability: occasional large outliers mimic real delays."""
    return float(np.random.lognormal(mean=np.log(target_hours), sigma=sigma))

Checkpoint: tms.db fills with orders, at least 15–20% flagged as late across all routes.

# Marco — Distribution Network Manager

You are Marco, a seasoned distribution network analyst with 15 years in luxury logistics.
Your job is to run the daily anomaly sweep across all 8 cities.

Your investigation style:
- Start with the big picture: which cities are drifting from their on-time targets?

Phase 3 — Write Agent Investigation Prompts

Week 6

Goal: Define the hourly investigation task for each of the 12 agents.

Each agent runs a structured investigation on its scope. For example, Elena (Transportation Manager) investigates misattributed delays:

Every hour, investigate misattributed delays:
1. Find all shipments where a team is flagged for a delay they did not cause
   (i.e., the preceding team's step ran over SLA and pushed this team past deadline)
2. Quantify how many such cases exist in the last 24 hours
3. Identify which upstream teams are generating most "cascade victims"
4. Post findings to #global-ops with evidence.

Phase 7 — Root Cause Analysis Automation

Week 11

Goal: Automate Elena's core value — systematically tracing which team actually caused a late delivery.

The cascade happens when Team A's overrun pushes Team B's completion past a hard constraint, making Team B's step appear delayed even though Team B ran within SLA.

def find_cascade_victims(order_id: str, conn) -> list[dict]:
    steps = pd.read_sql(
        "SELECT * FROM shipment_steps WHERE order_id=? ORDER BY started_at",
        conn, params=(order_id,)
    )
    victims = []
    cumulative_delay = 0.0

    for _, row in steps.iterrows():
        step_delay = row["actual_hours"] - row["target_hours"]
        if cumulative_delay > 0 and step_delay <= 0:
            # This step was on time, but inherited delay from upstream
            victims.append({
                "step": row["step_name"],
                "team": row["team"],
                "verdict": "CASCADE VICTIM — penalised for upstream overrun"
            })
        cumulative_delay += max(step_delay, 0)
    return victims
