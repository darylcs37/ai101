Executive Summary

This proposal outlines a structured internship project to build Workforce OS — a production-grade, self-hosted multi-agent operating system where every person on a team has their own AI agent managing their inbox, calendar, tasks, drafts, and cross-team collaboration, all coordinated through a shared git repository.


The core insight from the reference implementation (built and battle-tested at a real 7-person company in Singapore) is that AI assistants fail not because they lack intelligence, but because they are tourists, not residents of the workflow. Copilot, ChatGPT, and similar tools live in a sidebar — the real work lives in M365, Atlassian, and the terminal. Every session is a cold start. Ten minutes re-briefing the assistant is exactly the ten you were trying to save.


Workforce OS fixes this: agents read and write plain Markdown files, git is the coordination layer and audit trail, and the entire system is debuggable with ls and cat.

Problem Statement

A 7-person team × four hats each = constant context-switching. The overhead is the product. Typical AI assistant approaches fail on three dimensions:

Failure 1
Stateless sessions
Memory dies with the tab. Re-brief every morning.
Failure 2
No shared state
Per-user silos. No one sees what others' agents are doing.
Failure 3
No scope enforcement
"Don't send email" is a prayer, not a rule.

System Architecture

There is no database, no message queue, no hidden state. Every state change is a git commit — fully auditable. Any agent can be paused, inspected, or resumed by reading files.

new-task.sh — atomic ID counter with flock
#!/usr/bin/env bash
set -euo pipefail
TITLE="${1:?Usage: new-task.sh <title>}"
TODAY=$(date +%Y%m%d)
COUNTER_FILE="platform/.task-counter"
(
  flock -x 9
  COUNT=$(<"$COUNTER_FILE"); COUNT=$((COUNT + 1))
  echo "$COUNT" > "$COUNTER_FILE"
  printf -v PADDED "%04d" "$COUNT"
  TASK_ID="T-${TODAY}-${PADDED}"
  cat > "agents/cos/tasks/inbox/${TASK_ID}.md" <<EOF
---
id: ${TASK_ID}
title: "${TITLE}"
requester: "$(whoami)"
assigned_to: "cos"
status: inbox
priority: normal
created_at: "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
hop_count: 0
---
## Description
[Fill in]
## Acceptance Criteria
- [ ] [Add concrete checkable criteria]
EOF
  echo "Created: agents/cos/tasks/inbox/${TASK_ID}.md"
) 9>>"$COUNTER_FILE.lock"
Checkpoint./ops/new-task.sh "Prepare board deck" creates a valid task in CoS inbox. CoS session triages it and routes to the correct agent's inbox with a concrete output spec.
PHASE 3 Chief of Staff Agent + Multi-Agent Routing Week 3–4
GoalCoS operational. Two agents hand off work through the task system with zero manual file edits.

CoS has no human pair. It is the only entity that can promote drafts from shared/incoming/ to shared/knowledge/. Without CoS, agents become disconnected silos.

CoS Triage Checklist (every inbox item)
  1. Is the request specific enough to act on?
  2. Who owns this? Check agents/*/profile.md.
  3. What is the expected output? Must be a concrete file path or external artefact.
  4. Does it need splitting? One task = one owner = one output.
  5. Route: copy to assignee inbox → update frontmatter → log → move CoS copy to done.
End-to-End Demo Scenario
1. Human: ./ops/new-task.sh "Research AI safety frameworks for blog post"
   → T-YYYYMMDD-0002.md created in agents/cos/tasks/inbox/

2. CoS session: triages, routes to research agent with clear output spec
   → agents/research/tasks/inbox/T-YYYYMMDD-0002.md

3. Research agent: picks up task, moves to active/, researches, saves draft
   → agents/research/workspace/private/safety-frameworks.md

4. Research agent: moves draft to shared/incoming/, task to done/

5. CoS session: reviews draft, promotes to shared/knowledge/research/
   → git commit "[work][agent:cos] promote safety-frameworks research"
CheckpointFull handoff works with zero manual file edits. Every state change appears in git log with a timestamp.

GoalNo secrets can be committed. Agent write scope enforced by path. Per-machine identity prevents cross-wiring.
Autonomy Tiers — every soul.md must define all three

gitleaks pre-commit hook
#!/usr/bin/env bash
# ops/git-hooks/pre-commit
set -euo pipefail
STAGED=$(git diff --cached --name-only)
[[ -z "$STAGED" ]] && exit 0
if ! gitleaks protect --staged --no-banner -q; then
  echo ""
  echo "SECRETS DETECTED. Commit blocked."
  echo "Remove the secret, replace with [REDACTED-API-KEY],"
  echo "re-stage, commit. Rotate the real secret immediately."
  exit 1
fi

PHASE 8 validate.sh + CI Integration Week 8–9
GoalStructural health checks run locally before every commit and in GitHub Actions CI.
#!/usr/bin/env bash
# ops/validate.sh
set -euo pipefail; ERRORS=0
fail() { echo "FAIL: $1"; ERRORS=$((ERRORS+1)); }

# 1. Every agent has required files
for agent in agents/*/; do
  [[ "$agent" == "agents/_template/" ]] && continue
  for f in soul.md profile.md memory/context.md memory/routines.md \
            memory/lessons.md memory/decisions.md logs/activity.log.md; do
    [[ -f "${agent}${f}" ]] || fail "Missing: ${agent}${f}"
  done
done

# 2. Task status matches parent folder (folder IS the status)
for task in agents/**/tasks/**/*.md; do
  FOLDER=$(basename "$(dirname "$task")")
  STATUS=$(grep "^status:" "$task" | awk '{print $2}')
  [[ "$STATUS" == "$FOLDER" || "$STATUS" == "blocked" || \
     "$STATUS" == "cancelled" ]] || fail "Status mismatch: $task"
done

# 3. Only CoS has written to shared/knowledge/
NON_COS=$(git log --oneline --diff-filter=A -- shared/knowledge/ \
  | grep -v "\[agent:cos\]" | wc -l)
[[ "$NON_COS" -eq 0 ]] || fail "Non-CoS writes to shared/knowledge/ ($NON_COS)"

# 4. Secret scanning
gitleaks detect --no-banner -q 2>/dev/null || fail "Secrets detected"

# 5. hop_count check
for task in agents/**/tasks/**/*.md; do
  HOPS=$(grep "^hop_count:" "$task" | awk '{print $2}')
  [[ -z "$HOPS" || "$HOPS" -le 3 ]] || fail "hop_count > 3: $task"
done

[[ $ERRORS -eq 0 ]] && echo "All checks passed" || exit 1
CheckpointIntroducing a deliberate structural error (wrong frontmatter status) causes both local validate and GitHub Actions CI to fail loudly.
PHASE 9 Main CLI: workforce.sh Week 9–10
GoalDaily workflow reduced to one command. Full interface for every team member.
#!/usr/bin/env bash
# ops/workforce.sh
AGENT=$(awk -F= '/^agent_codename/{print $2}' ~/.config/workforce-os/identity)
case "${1:-launch}" in
  launch|"")
    git pull --rebase --autostash && ./ops/launch-agent.sh "$AGENT" ;;
  cos)
    git pull --rebase --autostash && ./ops/launch-agent.sh "cos" ;;
  task)
    ./ops/new-task.sh "${2:?Usage: workforce task <title>}" ;;
  sync)
    ./ops/validate.sh
    git add -A && git commit -m "[work][agent:$AGENT] mid-session sync" && git push ;;
  done)
    ./ops/validate.sh
    git add -A && git commit -m "[work][agent:$AGENT] end-of-day sync" && git push ;;
  status)
    echo "Agent: $AGENT"
    echo "Active: $(ls agents/$AGENT/tasks/active/ 2>/dev/null | wc -l) tasks"
    echo "Inbox:  $(ls agents/$AGENT/tasks/inbox/  2>/dev/null | wc -l) tasks"
    claude mcp list ;;
  help)
    echo "workforce               Launch your agent session"
    echo "workforce cos           Chief of Staff mode"
    echo "workforce task <title>  Create a new task"
    echo "workforce sync          Mid-session commit + push"
    echo "workforce done          End-of-day: validate, commit, push"
    echo "workforce status        Health check" ;;
esac

PHASE 10 Autonomous Agent: Chloe Week 10–12
GoalHeadless agent running hourly on cron with zero tools. All 12 safety layers operational.

Key principle: if Claude has no tools, prompt injection cannot trigger external actions. All publishing decisions are made by deterministic code, not the model.

cron fires agent-cycle.sh (hourly)
  → kill switch check      (platform/KILL_SWITCH file)
  → concurrency lock       (flock — no overlapping cycles)
  → circuit breaker check  (3 failures → 30 min cooldown)
  → budget check           (daily USD cap per agent)
  → git pull
  → data-fetching workers  (bash/python — deterministic, no Claude)
  → call Claude            (text in → structured JSON out, no tools)
  → post-processing        (file Jira issues, write drafts to shared/incoming/)
  → signed commit on agent/chloe branch
  → git push
12 Safety Layers
01
Zero ToolsClaude gets text, returns JSON — no filesystem or API access
02

03
Concurrency Lockflock prevents overlapping cycles
04

06

07
