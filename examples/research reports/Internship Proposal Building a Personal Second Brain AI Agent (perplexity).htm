Internship Proposal: Building a Personal "Second Brain" AI Agent

Based on Dr. Vivian Balakrishnan's keynote at AI Engineer Singapore, May 2026

Executive Summary

This proposal outlines a structured internship project to implement a self-hosted, compounding-memory AI assistant — a "Second Brain" — using the open-source stack demonstrated by Singapore's Minister for Foreign Affairs, Dr. Vivian Balakrishnan, at AI Engineer Singapore on 16 May 2026. The system transforms how an individual interacts with information, replacing stateless chatbots with a personal agent that accumulates knowledge over time, communicates via WhatsApp or Telegram, processes voice and documents, and synthesises facts into a structured, human-readable knowledge graph.[1][2][3]

The core thesis: real AI value is created at the edge — workflow by workflow, individual by individual — not only at the frontier model level. Barriers to building this system have already fallen; the components are open-source, battle-tested, and deployable on hardware as modest as a Raspberry Pi 5 with 8 GB RAM.[3][1]

Problem Statement

Standard LLM assistants are stateless — they forget everything between sessions. The common fix is RAG (Retrieval-Augmented Generation), but RAG retrieves raw text chunks, not synthesised knowledge. For high-cognitive-load professionals (diplomats, analysts, engineers, researchers), this creates three failure modes:[2]

  1. Context loss — every session requires re-briefing the model on background
  2. No accumulation — the system does not get smarter as you use it
  3. Cloud exposure — sensitive documents must be sent to third-party servers

The NanoClaw architecture solves all three: persistent graph-based memory, continuous knowledge compounding, and entirely local execution for sensitive content.[4][2]

System Architecture

The stack has three logical layers that mirror how human memory works: raw storage, structured recall, and narrative synthesis.[2]

Raw Sources → mnemon Knowledge Graph → Wiki Pages
(transcripts,    (structured facts,       (narrative summaries,
 articles,        graph nodes,             cross-referenced,
 web clips)       semantic retrieval)      browsable in Obsidian)

Core Components

Component Role Key Technology
NanoClaw orchestrator Message loop, container management, channel routing Node.js + TypeScript[2]
Claude Agent SDK Runs agent logic in isolated Docker containers per group Anthropic SDK[2]
Baileys WhatsApp Web protocol bridge (no business API needed) TypeScript library[6][7]
mnemon Custom CLI knowledge graph tool — SQLite + graph traversal Go binary[8]
Ollama + nomic-embed-text Local vector embeddings for semantic recall (no cloud calls) ~275 MB model, runs on Pi[2][9]
whisper.cpp Local voice transcription of WhatsApp voice notes On-device, private[2]
Obsidian IDE/frontend for viewing wiki pages, synced via iCloud macOS/iOS app[10]
Docker Container isolation — one container per agent group Container runtime[2]
SQLite Message store, group registry, task scheduler Embedded DB[2]

Memory Flow (on every agent invocation)

  1. User sends message via WhatsApp/Telegram
  2. Baileys delivers message to NanoClaw orchestrator
  3. mnemon runs a semantic query against the knowledge graph using nomic-embed-text embeddings
  4. Relevant facts are injected as system context before the Claude agent responds
  5. Agent response is returned to the user via the same channel
  6. New facts are extracted and written back to mnemon graph

Phase-by-Phase Implementation Guide

Phase 0 — Environment Setup (Week 1)

Goal: All prerequisites installed, Claude Code working, Docker running.

Steps:

  1. Install Node.js 20+ 
    # macOS
brew install node@20
# Ubuntu/Linux
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
  2. Install Docker Desktop — download from docker.com; ensure Docker daemon is running before proceeding[11]
  3. Install Claude Code and authenticate 
    npm install -g @anthropic-ai/claude-code
claude login
# Verify: claude --version
    Claude Code is mandatory — NanoClaw's /setup workflow runs entirely inside it[12][11]
  4. Install Ollama (for local embeddings) 
    # macOS
brew install ollama
brew services start ollama
# Pull the embedding model
ollama pull nomic-embed-text
    The nomic-embed-text model is ~275 MB and runs efficiently on CPU-only hardware including Raspberry Pi 5[9][2]
  5. Install mnemon (knowledge graph CLI) 
    brew install mnemon-dev/tap/mnemon
# or via Go
go install github.com/mnemon-dev/mnemon@latest
# Verify
mnemon --version
mnemon setup   # auto-detects Claude Code
    mnemon is an LLM-supervised graph — the host LLM makes judgment calls (what to remember, how to link, when to forget); the binary handles deterministic storage and retrieval[8]

Checkpoint: Run node --version && docker --version && claude --version && ollama list && mnemon --version — all must return versions.

Phase 1 — NanoClaw Core Setup (Week 2)

Goal: NanoClaw running, able to receive and respond to one test message.

Steps:

  1. Fork and clone the repository 
    gh repo fork qwibitai/nanoclaw --clone
cd nanoclaw
  2. Open Claude Code inside the project directory 
    claude
    Important: always launch claude from within the nanoclaw/ folder — the /setup skill reads the project's CLAUDE.md and project structure[12]
  3. Run the guided setup skill 
    /setup
    Claude will automatically: install all npm dependencies, create .env with your Anthropic API key, build the Docker container image, configure the system service (launchd on macOS, systemd on Linux), and start NanoClaw in the background[11]
  4. Verify the service is running 
    # Linux
systemctl --user status nanoclaw
# macOS — check via Console.app or:
ps aux | grep nanoclaw
  5. Send a test message — from inside claude, type a plain message. Confirm a Claude response appears.

Checkpoint: Agent responds to a basic text message with no errors in logs.

Phase 2 — WhatsApp Channel Integration (Week 3)

Goal: Communicate with the agent via WhatsApp on your personal phone.

Steps:

  1. Add WhatsApp channel — inside claude, run: 
    /add-whatsapp
  2. Scan QR code — Claude will display a terminal QR code. On your phone: WhatsApp → Settings → Linked Devices → Link a Device → Scan[11]
  3. Test the connection 
    @Andy hello
    You should receive a response in the same chat within seconds.

About Baileys: The WhatsApp integration uses Baileys, a TypeScript library that connects to the WhatsApp Web WebSocket protocol using the Linked Devices feature. It does not use the official WhatsApp Business API. As a result, it is technically unofficial — acceptable for personal/research use but should not be used in production commercial deployments.[13][6][7]

Telegram alternative — if WhatsApp is unsuitable for your context, use Telegram instead: 

/add-telegram
This requires creating a bot via @BotFather on Telegram, then providing the bot token.[11]

Checkpoint: Two-way messaging via WhatsApp, agent trigger word (@Andy) works reliably.

Phase 3 — Memory System & Knowledge Graph (Weeks 4–5)

Goal: Agent accumulates and recalls knowledge across sessions.

Background: The mnemon knowledge graph stores facts as discrete nodes with content, category, importance scores, tags, timestamps, and graph edges to related entries. This is fundamentally different from RAG: instead of retrieving raw text, mnemon retrieves synthesised, linked facts that have been validated and deduplicated by the LLM supervisor.[8][2]

Steps:

  1. Ingest your first source documents — place markdown files in the groups/global/transcripts/ directory. These can be meeting notes, articles, or speeches[2]
  2. Trigger the ingest pipeline — inside claude: 
    ingest the documents in transcripts/ into the knowledge graph
  3. Test semantic recall — send a question about the ingested content via WhatsApp: 
    @Andy what are the key points from [document topic]?
    Verify that the agent surfaces specific facts from the graph, not just generic LLM knowledge.
  4. Configure the article watcher (optional but recommended) — NanoClaw includes a watch-articles.sh script using inotifywait that automatically triggers an ingest task whenever new files appear in a watched folder:[2] 
    # The watcher is managed by systemd — enable it:
systemctl --user enable nanoclaw-article-watcher
systemctl --user start nanoclaw-article-watcher
  5. Explore the mnemon graph structure — the graph maintains two stores:
    • Global store — shared knowledge across all groups; read-only for non-main agents
    • Local store — per-group memory, writable only by that group's agent[2]

Checkpoint: Agent correctly references specific ingested facts when asked, and the mnemon graph is growing as new documents are processed.

Phase 4 — LLM Wiki Synthesis (Weeks 5–6)

Goal: Implement Andrej Karpathy's LLM Wiki pattern to compile raw facts into a human-readable, cross-linked knowledge base browsable in Obsidian.

Background: Karpathy's LLM Wiki approach (shared April 2026) compiles raw documents into a structured wiki of .md files organised into concepts, entities, and timelines. Unlike indexing documents whole, the LLM reads each source once and writes synthesised, interlinked articles. The wiki grows incrementally as new sources are added.[10][14][15]

Steps:

  1. Set up Obsidian vault structure 
    vault/
  raw/          ← source documents (never modified by agent)
  knowledge/
    entities/   ← people, organisations
    concepts/   ← topics, ideas
    timelines/  ← chronological views
  2. Create a CLAUDE.md schema file in the vault root — this instructs the LLM how to structure wiki articles, what categories to use, and how to cross-reference entries. Example:[14] 
    # Wiki Schema
## Article format
Each article covers one entity or concept.
Include: definition, key facts, cross-references (wikilinks), and sources.
## Categories
- entities/: People, organisations, places
- concepts/: Ideas, frameworks, policies
- timelines/: Events ordered by date
  3. Trigger wiki compilation — inside claude or via WhatsApp: 
    @Andy compile the wiki from documents in raw/
  4. Set up Obsidian sync to mobile — Dr. Balakrishnan's approach uses iCloud + rsync from a Mac Mini. A simpler alternative for an internship context is git-based sync or Obsidian Sync.[2]
  5. Add the Obsidian Web Clipper browser extension — this lets you clip web articles directly into the raw/ folder for automatic ingestion[10]

Checkpoint: Obsidian vault contains auto-generated wiki articles with wikilinks between entries. Asking the agent a complex cross-topic question returns answers that cite specific wiki articles.

Phase 5 — Voice Interface (Week 7)

Goal: Send voice notes via WhatsApp; agent transcribes and responds.

NanoClaw uses whisper.cpp, a lightweight C++ port of OpenAI's Whisper ASR model, to transcribe voice notes entirely on-device. This keeps audio content private — nothing is sent to cloud services.[2]

Steps:

  1. Verify whisper.cpp is installed — the /setup skill installs it automatically. Confirm with: 
    which whisper-cpp
  2. Send a voice note — in WhatsApp, hold the microphone button and speak. NanoClaw will:
    • Receive the audio file via Baileys
    • Transcribe it using whisper.cpp (base model)
    • Pass the transcript to the Claude agent as a text message
    • Respond in text (or voice, if TTS is configured)
  3. Test with a complex query — try a spoken factual question about ingested documents to verify the full voice → transcription → graph recall → response pipeline.

Checkpoint: Voice notes are transcribed correctly; agent responds with relevant knowledge-graph-informed answers.

Phase 6 — Task Scheduler & Automated Briefings (Week 8)

Goal: Schedule recurring tasks such as morning briefings, news summaries, and reminder queries.

Steps:

  1. Create a scheduled briefing — via WhatsApp: 
    @Andy every weekday at 8am, give me a morning briefing: top 3 AI news, any scheduled meetings, and one fact from my knowledge graph
  2. Configure pre-check scripts — for tasks that check external conditions (e.g., "did any new articles arrive?"), use a bash pre-check script. The scheduler only wakes the agent if the script returns wakeAgent: true. This minimises API token usage:[2] 
    #!/bin/bash
# pre-check.sh — check if new articles exist
count=$(find /path/to/raw -newer /tmp/last-check -name "*.md" | wc -l)
if [ "$count" -gt 0 ]; then
  echo '{"wakeAgent": true}'
else
  echo '{"wakeAgent": false}'
fi
touch /tmp/last-check
  3. Test cron, interval, and one-time tasks — NanoClaw's scheduler supports all three modes[2]

Checkpoint: At least one recurring scheduled task runs autonomously without manual trigger.

Phase 7 — Security Hardening (Week 9)

Goal: Apply production-grade security controls appropriate for sensitive personal data.

Dr. Balakrishnan's security approach: "only put what is already open source, what is already published, and subject your systems to transparency and scrutiny that can be withstood". For more sensitive deployments, additional controls are needed.[1]

Key security controls to implement:

Control Implementation
API key isolation Containers never see raw API keys — OneCLI proxy intercepts HTTPS and injects credentials[2]
Sender allowlist Only authorised phone numbers/users can trigger the agent[2]
Mount allowlist Stored outside project root; blocks sensitive paths (.ssh, .aws, *.pem)[2]
Per-group IPC namespacing Each group can only send to its own JID; identity verified by directory path, not message content[2]
Local embeddings nomic-embed-text runs on-device — knowledge base content never leaves the machine[2]
Local transcription whisper.cpp on-device — voice notes stay private[2]

Additional hardening for enterprise contexts:

  • Enable Docker network policies to restrict container egress
  • Rotate Anthropic API keys on a schedule
  • Set up log monitoring for unexpected container spawns
  • Consider running on an isolated VLAN if connecting to sensitive internal documents

Phase 8 — Evaluation & Documentation (Weeks 10–11)

Goal: Measure system performance, identify gaps, and produce handover documentation.

Evaluation criteria:

Metric Target How to Measure
Memory recall accuracy >80% of ingested facts retrievable Test set of 20 factual Q&A pairs
Response latency (WhatsApp) <10 seconds end-to-end Stopwatch from send to receive
Voice transcription WER <10% word error rate Compare whisper output to ground truth
Uptime over 7-day period >99% System monitoring logs
Wiki article quality Human review by supervisor Coherence, cross-links, accuracy
API cost per day Track and stay within budget Anthropic usage dashboard

Documentation deliverables:

  1. Architecture diagram (draw.io or Mermaid)
  2. Setup guide for a new user starting from zero
  3. CLAUDE.md templates for different use cases (diplomat, developer, researcher)
  4. Known limitations and failure modes log
  5. Recommended extensions (Gmail integration, subagent teams, Obsidian mobile sync)

Technical Prerequisites for the Intern

Required:

  • Comfortable with Linux/macOS terminal (bash commands, file navigation)
  • Basic understanding of Docker containers
  • Node.js/TypeScript familiarity (read and debug code, not necessarily write from scratch)
  • Git workflow (fork, clone, commit, push)

Helpful but not required:

  • Go (mnemon is a Go binary — useful for deep debugging)
  • Networking fundamentals (for security phase)
  • Understanding of vector embeddings and semantic search

Not required:

  • ML/AI research background
  • Experience with Anthropic APIs (Claude Code handles most abstraction)
  • Raspberry Pi hardware (any Linux server or developer laptop suffices)

As Dr. Balakrishnan noted: "I didn't write any code. I was just assembling tools" — the project is fundamentally about composing existing open-source components, not building from scratch.[16][1]

Expected Outcomes

By the end of the internship, the intern will have:

  1. A working personal AI agent — self-hosted, runs 24/7, communicates via WhatsApp
  2. A compounding knowledge base — mnemon graph + Obsidian wiki that grows with each ingested document
  3. Practical LLM systems experience — agent orchestration, memory architectures, container isolation, local embeddings
  4. Security-aware system design skills — applied to a real system with personal/sensitive data
  5. A replicable template — setup guide and CLAUDE.md templates usable by others in the organisation
